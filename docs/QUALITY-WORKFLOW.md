# Skill 质量工作流

本文档定义仓库内 skill 的共享运行纪律，适用于日常调用和维护评审。

## 运行流程

1. 识别输入：URL、文件、输出目录、指定后端或模式，以及用户是否已经做出明确选择。
2. 从 `SKILL.md` 选择风险最低的已记录流程。
3. 对低风险公开视频和默认输出位置直接运行。
4. 触发高影响门时，先给出短确认计划。
5. 执行辅助脚本。
6. 汇报成功前检查运行后的事实源。
7. 对安全可恢复的失败先重试或修复。
8. 用完成模板汇报成功、部分成功或阻塞。

## 高影响门

出现以下情况时先停下来确认：

- 浏览器 cookie 或登录态。
- 付费 API 调用。
- 将私密、敏感或大文件媒体上传到外部 API。
- 大型播放列表或其他高批量处理。
- agent 自行选择的非默认输出路径。
- 覆盖风险或使用 `--force`。
- 后端选择含糊，且不同路径在费用或隐私上差异明显。

如果用户已经明确选择低风险变化，例如 `--audio-only` 或指定输出目录，不要为同一个选择重复确认，除非还触发了其他高影响门。

## Doctor 与 Dry Run

工具型 skill 应在可行时提供 `--doctor` 和 `--dry-run`。

- `--doctor` 检查本地命令、Python 模块、虚拟环境状态、重要环境变量存在性和轻量 endpoint 配置。它不证明第三方服务一定可用。
- `--dry-run` 预览输入、可能输出、后端选择、字幕或播放列表 metadata、隐私/费用风险和已有产物 skip 行为。它不得下载媒体、上传文件或转写音频。

如果脚本还不能提供完整 doctor 或 dry run，应记录缺口并提供最接近的离线检查。

## 事实源

agent 必须在汇报完成前检查事实源。

- `video-transcript`：每视频 `metadata.json`、输出目录、`original.md`、可选 `zh.md`，以及存在时的运行级 summary。
- `yt-dlp-download`：输出目录、媒体文件、字幕 sidecar、缩略图 sidecar、`.yt-dlp-archive.txt`，以及存在时的 `download-summary.json`。

当 metadata 或 summary 存在时，只有目录存在还不够。

## 自检

汇报成功前：

- 确认必需输出存在，并在预期时非空。
- 确认 summary 或 metadata 状态与磁盘文件一致。
- 确认跳过项标为 `skipped`，不能标为 `success`。
- 确认部分失败列出重试建议。
- 确认 warnings 没有被隐藏。
- 确认 docs、examples、manifests、summaries、metadata 中没有写入 secret。

如果失败可安全恢复，先重试或修复。若需要凭据、用户选择、外部服务访问或 agent 无法安装的依赖，把它汇报为 `blocked`，并给出最小下一步。

## 显式退化

缺依赖、凭据、外部 skill 或登录态时，从以下路径选择：

- 安装或配置缺失依赖。
- 切换到已记录的低风险后端。
- 跳过受影响阶段并标为 `skipped`。
- 汇报 `blocked`，说明受影响项、缺失条件和下一步。

不要创建空壳 placeholder 产物并声称成功。

## 续跑与 Force

批量和高成本工作应可续跑：

- 默认行为应复用有效成功产物，只重试失败或缺失项。
- `--force` 表示用户接受覆盖或重新下载成功产物。
- 只重试失败项时，应避免重复付费上传或重复下载已完成项，除非失败项必须这样做。
- 不确定输出路径必须标记 `uncertain_path`。

## 完成模板

skill 最终汇报使用这个形状：

```text
状态：success | partial | blocked | failed
输出：<主要输出路径>
事实源：<metadata 或 summary 路径>
警告：<重要警告或无>
失败或跳过项：<项目和原因或无>
下一步：<查看输出、翻译、重试、提供 key、安装依赖、运行验证>
```

## Reviewer Handoff

独立 reviewer 是增强项，不替代当前 agent 的本地自检。

使用 reviewer 时提供：

- 产物路径。
- 事实源路径。
- 要执行的检查清单。
- 风险边界。
- reviewer 不得修改的文件或目录。
- 要求输出：`pass` 或 `fail`、证据、建议、是否阻塞交付。

## 反馈回流

用户反馈问题时：

- 先定位层级：输入理解、后端选择、下载、转写、字幕、输出契约、summary、文档、安装元数据或验证。
- 修改最小相关文件或产物。
- 行为或状态变化时更新事实源。
- 说明哪些派生产物需要重建。
- 能窄修时不要重跑全流程。

## 边界

本仓库不在此 change 中引入主题系统、skill 调用链 registry 或下载/转写组合 pipeline skill。这些能力如果需要，应后续单独开 change。工具型 skill 不应继承无关工作流 skill 的 Vite、React、音频旁白、录屏或主题机制。
