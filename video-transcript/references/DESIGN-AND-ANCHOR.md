# Frontend Design 与富格式 anchor

本文档定义富格式输出的设计 checkpoint、设计 brief、anchor 样张和渲染 QA。适用于 HTML、PPTX、Word/DOCX 和 PDF 等非默认 Markdown 产物。所有生成文档必须使用中文。

## Frontend Design checkpoint

默认使用朴素模板，不需要设计时不要调用 Frontend Design 流程。只有在用户要求“做得好看”“网页展示”“演示稿风格”“品牌化”“可发布页面”“课程视觉稿”等明显需要视觉设计的场景，才进入设计 checkpoint。

不需要暂停的情况：

- 用户只要 Markdown 转写或纯文本整理。
- 用户已给定明确模板、品牌规范或既有版式，并要求直接套用。
- 输出只是中间稿、审校稿或机器处理用文件。

需要确认时使用：

```text
这次输出需要设计稿吗？
- 朴素模板：结构清楚，最快，适合审阅和归档。
- 设计增强：会先写设计 brief，再做 anchor 样张和渲染 QA，适合发布或演示。

确认后我再继续。
```

如果用户初始请求已经明确要求设计增强，不要二次暂停；直接生成设计 brief 并进入 anchor。

## 设计 brief

设计增强时先写 `frontend-design-brief.md` 或等价 section。可使用 [`../templates/frontend-design-brief.template.md`](../templates/frontend-design-brief.template.md)。

brief 至少说明：

- 目标读者和使用场景。
- 输出格式和阅读设备。
- 信息层级：标题、摘要、章节、重点、公式、引用、行动项。
- 视觉方向：字体气质、颜色、密度、留白、图表和代码块处理。
- 约束：中文优先、可读性、可打印、可访问性、不得泄露 secret。
- QA 计划：截图、渲染页、公式页、移动/桌面或页面尺寸检查。

## 设计后自检

进入完整生成前，先检查 brief 和素材是否足够：

- 设计目标是否服务内容，而不是装饰内容。
- 中文长标题、英文术语、公式和代码不会溢出。
- 颜色对比度足够，打印或投影仍可读。
- HTML 在首屏和移动宽度下不遮挡正文。
- PPTX 每页信息密度适合讲解，不把转写全文硬塞进幻灯片。
- DOCX 标题层级、页眉页脚、目录和公式可编辑或可追溯。

设计增强失败时，回退到朴素模板，并在 run-manifest 写明原因。

## 富格式 anchor

anchor 是完整生成前的小范围样张，用来验证结构、视觉、公式和导出链路。

触发条件：

- 首次为当前内容生成 HTML、PPTX、Word/DOCX 或 PDF。
- 用户要求设计增强、品牌化或发布级输出。
- 内容包含复杂公式、表格、代码块、大量截图或多语言排版。
- 输出文件会很长，完整生成成本高。

anchor 范围：

- HTML：首屏或首章，必须包含标题、元信息、一个正文段落、一个二级标题，以及存在时的公式/代码/表格样例。
- PPTX：前 2-3 页，通常是封面、目录/摘要、第一节内容页。
- Word/DOCX：前 1-2 页，通常是封面/标题区和第一节正文。
- PDF：不直接制作独立 anchor；从 HTML、DOCX 或 PPTX anchor 派生，除非用户只要求 PDF。

## anchor 验收项

- 中文文本完整可读，无明显截断、重叠或乱码。
- 标题层级、章节节奏和元信息位置合理。
- 公式、代码、表格和引用至少覆盖一个代表性样例。
- HTML 首屏在桌面和移动尺寸可读；PPTX 在 16:9 放映尺寸可读；DOCX 在页面预览中可读。
- 视觉方案与 brief 一致；若使用朴素模板，版式仍清楚克制。
- QA 证据已记录到 run-manifest 或汇报中。

## 渲染 QA

完成富格式输出前必须做可见渲染检查，而不是只检查文件存在。

- HTML：打开本地页面或浏览器截图，检查首屏、首章、公式渲染和移动宽度。
- PPTX：渲染前 2-3 页和至少一页公式/密集内容页。
- DOCX：渲染或预览前 1-2 页和至少一页公式/表格页。
- PDF：检查首页、公式页和最后一页。

QA 证据可以是截图路径、渲染命令、页码列表、人工检查摘要或工具输出摘要。证据不需要包含 secret 或私密正文全文。

## 可跳过边界

可以跳过 anchor 或设计 checkpoint，但必须说明原因：

- 用户明确只要 Markdown 或朴素文档。
- 内容很短，完整产物等同于 anchor。
- 用户已提供固定模板，并要求直接生成。
- 任务是修补已有富格式文件的局部问题。
- 当前环境缺少渲染工具；此时要记录无法完成的 QA 项和建议补验方式。

跳过记录示例：

```json
{
  "anchor": {
    "status": "skipped",
    "reason": "用户明确要求仅生成朴素 Markdown",
    "qa_required": false
  }
}
```
